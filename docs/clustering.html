6  Clustering

“There are more things in heaven and earth, Horatio,
Than are dreamt of in your philosophy.”
— William Shakespeare, in “Hamlet”

Clustering is one of the most fundamental tasks in data analysis: given a dataset, group the points into meaningful subsets. It sounds simple, but the devil is in the details. What does “meaningful” mean? How many clusters should there be? And what shape can they have?

In this chapter we cover classical clustering methods, their strengths and limitations. They also supply useful baselines for the density-and-persistence approach of ToMATo. Topology does not relieve us of choosing what similarity should mean.

6.1 What is a clustering?

Definition 6.1 A clustering of a set \(X\) is a collection \(C_1, \ldots, C_n \subset X\) such that \(\bigcup C_i = X\) and \(C_i \cap C_j = \emptyset\) for any \(i \neq j\). In other words: it is a partition of \(X\) into disjoint subsets. Each \(C_i\) is called a cluster.

A clustering method assigns a label to each point, often after we choose a metric and parameters. Methods that allow unassigned points commonly reserve label 0 for noise. That is useful bookkeeping, but the noise points need not form one coherent cluster.

Let’s load some packages and datasets to work with:

function load_fcps(name)
    data = readdlm("clustering datasets/$name.csv", ',', Any)
    points = permutedims(Float64.(data[2:end, 2:end]))
    labels = Int.(data[2:end, 1])
    return points, labels
end

6.2 Before choosing an algorithm, choose a distance

Our matrices have one point per column, and all examples use Euclidean distance. We retain the benchmark coordinates so that radius values can be compared with the later ToMATo chapter. For measurements in different units, an unscaled distance can be dominated by whichever coordinate has the largest numerical spread. Standardizing each feature to mean zero and standard deviation one is one possible remedy:

function standardize_features(M)
    scales = std(M, dims = 2)
    # A constant feature contributes no distance; avoid division by zero.
    scales[scales .== 0] .= 1
    (M .- mean(M, dims = 2)) ./ scales
end

# Optional alternative geometry; the examples below retain hepta_pts.
hepta_standardized = standardize_features(hepta_pts)

Standardization is a modeling decision: it changes distances, neighborhoods, and clusters. Outliers can affect its mean and variance, and giving every feature equal variance can amplify irrelevant measurements. Record units, missing-value handling, and scaling before comparing algorithms. If you later evaluate a classifier, estimate these transformations on training data and reuse them on test data.

6.3 K-means

The most popular clustering algorithm is k-means. The idea is simple:

  1. Choose \(k\) initial cluster centers (centroids)
  2. Assign each point to the nearest centroid
  3. Recompute centroids as the mean of assigned points
  4. Repeat steps 2-3 until convergence
# K-means on Hepta (k=7, since we know there are 7 clusters)
result_hepta = kmeans(hepta_pts, 7)
km_labels_hepta = assignments(result_hepta)

fig = Figure(size = (800, 400))
ax1 = Axis3(fig[1, 1], title = "Hepta: true labels")
scatter!(ax1, hepta_pts[1,:], hepta_pts[2,:], hepta_pts[3,:], 
    color = hepta_labels, markersize = 5)
ax2 = Axis3(fig[1, 2], title = "Hepta: k-means (k=7)")
scatter!(ax2, hepta_pts[1,:], hepta_pts[2,:], hepta_pts[3,:], 
    color = km_labels_hepta, markersize = 5)

K-means minimizes the sum of squared Euclidean distances to the assigned centroids. Compact, separated groups suit this objective, so Hepta is a friendly first example. The algorithm does not formally assume that every cluster is a sphere, but its nearest-centroid assignment partitions the ambient space into convex Voronoi cells. What happens with less friendly shapes?

This two-centroid fit cuts across the ring. A nearest-centroid boundary cannot separate a ring from an enclosed core. Limitations of k-means:

  • Its nearest-centroid regions are convex; elongated and nested groups may be split
  • Requires knowing \(k\) in advance
  • Sensitive to initialization
  • Sensitive to outliers

6.4 DBSCAN

DBSCAN (Density-Based Spatial Clustering of Applications with Noise) builds clusters through connected chains of dense neighborhoods (Ester et al. 1996).

Conventional DBSCAN has two main parameters, the neighborhood radius and the core-point count. This package exposes an additional rule for accepting a finished cluster:

  • \(\epsilon\): the radius of a neighborhood
  • min_neighbors: the minimum neighborhood count required for a core point (the package counts the point itself)
  • min_cluster_size: the minimum accepted size of a resulting cluster
# DBSCAN on Target
D_target = pairwise(Euclidean(), target_pts, dims = 2)
result_db = dbscan(D_target, 0.5; metric = nothing,
    min_neighbors = 10, min_cluster_size = 10)

# dbscan returns a DbscanResult; extract cluster assignments
db_labels = zeros(Int, size(target_pts, 2))
for (i, cluster) in enumerate(result_db.clusters)
    db_labels[cluster.core_indices] .= i
    db_labels[cluster.boundary_indices] .= i
end

fig = Figure(size = (800, 400))
ax1 = Axis(fig[1, 1], title = "Target: true labels", aspect = DataAspect())
scatter!(ax1, target_pts[1,:], target_pts[2,:], 
    color = target_labels, markersize = 4)
ax2 = Axis(fig[1, 2], title = "Target: DBSCAN", aspect = DataAspect())
scatter!(ax2, target_pts[1,:], target_pts[2,:], 
    color = db_labels, markersize = 4)

metric = nothing tells this API that the input is already a distance matrix. Without it, the columns would be interpreted as observations in a different space. Alternatively, pass target_pts with metric = Euclidean() and the same radius and count settings.

DBSCAN permits non-convex clusters and does not require a requested cluster count. Its count still depends on radius and density thresholds. The plotting label 0 marks unassigned points, which can be scattered across the figure.

Limitations of DBSCAN:

  • Struggles with clusters of varying density
  • Sensitive to \(\epsilon\) and neighborhood count parameters
  • Neighborhood-distance plots and domain scales help choose parameters, but should be checked across a range

6.5 Hierarchical clustering

Hierarchical clustering builds a tree (called a dendrogram) that shows how points are progressively merged into clusters:

  1. Start with each point as its own cluster
  2. Merge the two closest clusters
  3. Repeat until everything is in one cluster

The “distance between clusters” can be defined in several ways (single linkage, complete linkage, average linkage, Ward’s method, etc.).

# Hierarchical clustering on Lsun
D_lsun = pairwise(Euclidean(), lsun_pts, dims = 2)
hc = hclust(D_lsun, linkage = :ward)

# Cut at 3 clusters
hc_labels = cutree(hc, k = 3)

fig = Figure(size = (800, 400))
ax1 = Axis(fig[1, 1], title = "Lsun: true labels", aspect = DataAspect())
scatter!(ax1, lsun_pts[1,:], lsun_pts[2,:], 
    color = lsun_labels, markersize = 4)
ax2 = Axis(fig[1, 2], title = "Lsun: hierarchical (Ward, k=3)", aspect = DataAspect())
scatter!(ax2, lsun_pts[1,:], lsun_pts[2,:], 
    color = hc_labels, markersize = 4)

Ward’s method merges groups to control the increase in within-group squared Euclidean variation. Its geometric interpretation depends on Euclidean input; replacing the distance matrix by an arbitrary dissimilarity does not preserve that interpretation. Other linkages answer different questions.

The dendrogram encodes a nested sequence of partitions. Single linkage has a precise connection to \(H_0\) persistence of the Rips filtration: at radius \(r\), its clusters are the components of the graph joining points at distance at most \(r\). Ward, complete, and average linkage do not have this correspondence. An \(H_0\) barcode records merge scales, but loses the information about which labeled points merged that the dendrogram retains.

hc_single = hclust(D_lsun, linkage = :single)
(ward_sizes = counts(hc_labels),
 single_sizes = counts(cutree(hc_single, k = 3)))
(ward_sizes = [177, 157, 66], single_sizes = [200, 100, 100])

Single linkage follows chains of short edges and can therefore connect distant populations through a few intermediate points. This is useful for some geometries and a nuisance for others.

6.6 Comparing models of a cluster

Each of the methods above has assumptions that can fail:

Method What we choose; common difficulty
K-means \(k\), scaling, initialization; nested or elongated groups
DBSCAN Radius and neighborhood counts; a shared threshold can struggle with very different densities
Hierarchical Metric, linkage, cut level; the linkage controls which merges are favored
ToMATo Density bandwidth, proximity graph, peak lifetime and height thresholds; errors in any ingredient propagate

ToMATo combines mode seeking with persistence-based merging. It gives us a plot of peak lifetimes that helps inspect a choice of threshold; it still needs parameters and can still disagree with the benchmark labels. First, we need to understand persistent homology so that the diagnostic has a clear meaning.

6.7 Try it yourself

  1. Multiply the first coordinate by 100. Predict what happens to Euclidean neighborhoods, then rerun a clustering.
NoteWorked answer

A difference in that coordinate contributes 10,000 times as much to squared Euclidean distance. Radius neighborhoods shrink in that direction, and k-means prioritizes fitting that coordinate. Standardization restores the original relative scales only if equal feature variance is the intended geometry.

  1. Can one DBSCAN noise label or one k-means cluster be interpreted automatically as a biological population?
NoteWorked answer

No. Noise is a rule for points that do not satisfy the chosen density conditions; it need not be connected. A fitted cluster is a group under the chosen metric and objective. A population interpretation requires relevant measurements and validation outside the algorithm.

  1. Which hierarchy matches Rips \(H_0\) persistence, and what extra information does its dendrogram retain?
NoteWorked answer

Single linkage matches the connected components and their merge scales. Its labeled tree also records which points and clusters merge. The barcode retains the scales and multiplicities, not those memberships.
